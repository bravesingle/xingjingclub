# 微信支付真实接入 · 测试指南（星竞电竞）

> 适用：已按《微信支付接入说明》完成代码接入、开关翻转、证书就位后，验证整条链路是否通。

---

## 0. 测试前置（缺一不可，先自检）

| 项 | 要求 | 检查方法 |
| --- | --- | --- |
| 后端 `.env` | `PAY_MOCK=false`、`WECHAT_MOCK=false`、`WECHAT_SECRET` 已填 | `cat server/.env` |
| 证书 | `server/certs/apiclient_key.pem` 等 3 个文件存在 | 目录看一眼 |
| 后端可达 | `https://你的域名/api/home/data` 返回 `{code:0,...}` | 浏览器打开 |
| 小程序开关 | `config/index.js`: `env:'prod'`、`useMockPay:false`、`anonLogin:false` | 打开文件确认 |
| 合法域名 | `api.xingjingclub.cn` 已加小程序后台「服务器域名」白名单（request/socket） | mp.weixin.qq.com → 开发管理 → 开发设置 |

> ⚠️ 微信**正式版/真机**只能用「已备案 HTTPS 域名」，不能用裸 IP、不能用 `http://`。
> 所以真实支付测试前，域名备案 + HTTPS 必须已就位。否则只能停留在开发者工具模拟阶段。

## 1. 阶段一：不花钱的链路自测（可选，先确认后端没写错）

后端 `PAY_MOCK=true` 时跑一遍旧 mock 流程（登录→下单→支付）确认无回归；
再把 `PAY_MOCK=false` 后**只测"下单参数校验"**：

```
POST https://你的域名/api/pay/wechat/prepay
Header: Authorization: Bearer <真实登录token>
Body: { "orderId": 123 }
```

预期结果分两种：
- 返回 `mock:false` 且带 `payParams` → 说明下单请求已发到微信并成功（能走到这步说明签名/证书/序列号基本正确）✅
- 返回 400 及中文错误 → 按错误排查（见第 5 节）

> 注意：`prepay` 需要真实登录 openid。若 token 是 mock 登录拿的，会报
> `当前为模拟登录，无法发起微信支付`——这是预期保护，先用真实登录。

---

## 2. 阶段二：开发者工具里的假支付（不扣钱）

微信开发者工具 → 详情 → 勾选「不校验合法域名」→ 用**正式 AppID**（体验版/开发版）：

1. 走完整流程：登录 → 下单 → 收银台选"微信支付"
2. 开发者工具会拉起**模拟支付**弹窗（不会真扣款）
3. 看后端日志是否走到真实 prepay（会打印微信返回/下单成功），工具内点"支付成功"模拟

作用：验证**前端传参与后端返回参数拼接正确**（`timeStamp/nonceStr/package/paySign`）。

> 开发者工具的"模拟支付"只是前端模拟，**不会触发微信回调**，不能验证后端置 paid 逻辑。

---

## 3. 阶段三：真机小额真实支付（1 分钱验证全链路）

这是**唯一能完整验证**收款的测试：

1. 把后端部署到公网（备案域名 + HTTPS 正常），`PAY_MOCK=false`
2. 小程序：开发者工具 → 上传代码 → 微信后台设为**体验版**；或直接预览到真机
3. 真机打开 → 登录 → 下单 → 选微信支付 → 弹出**真实微信收银台**
4. 支付 **¥0.01**（微信最低支付金额），输密码/指纹完成支付
5. **支付成功后回到小程序**，观察：
   - 约 1~2 秒后订单状态自动变"已支付"（由回调驱动）
   - 后端日志出现：`✅ 微信支付成功: order=... tx=...`
6. 商户平台（pay.weixin.qq.com）→ 交易账单：能查到这笔 0.01 元交易 → 说明商户侧收单成功

**通过标准**：真机扣了 1 分钱 + 回调把订单置 paid + 商户平台能查到交易 = 全链路通。

> 测试完这 1 分钱可走站内退款或留着，别急着关开关。

## 4. 阶段四：回调与异常场景验证

### 4.1 回调正常性
支付完成后若订单没自动变已支付，多半是回调没送达。验证方法：
- 商户平台 → 产品中心 → 开发配置 → 支付回调通知：确认 notify_url 填的就是
  `https://api.xingjingclub.cn/api/pay/wechat/notify`
- 用 curl 模拟微信重试？不行（需微信签名）。只能重新发起一笔 1 分钱支付看日志
- 后端日志无 `✅` 但有 `微信回调处理失败` → 看具体报错

### 4.2 幂等（重复回调不重复入账）
微信会重试回调。连续收到同一笔回调时，后端应只成功置 paid 一次。
验证：手动在日志确认同一 order 只出现一次 `✅`（代码已按订单状态做幂等）。

### 4.3 金额不符
改订单金额后再回调会返回失败并告警（预期保护）。正常业务不会触发。

### 4.4 收不到回调时的兜底
小程序端有 `queryPayResult` 轮询接口可查订单状态；若回调丢了且用户已付款，
后端可后续补"主动查单"接口（调用微信 `GET /v3/pay/transactions/out-trade-no/{no}`）
对账修正。当前未实现，属于已知待办。

## 5. 常见报错排查表

| 报错/现象 | 原因 | 处理 |
| --- | --- | --- |
| `当前为模拟登录…` | 用的是 mock token | 用真实微信登录（`WECHAT_MOCK=false` + 真 secret） |
| `微信支付请求失败: 商户号类型不正确 / sub_mchid…` | 特约商户需走服务商模式 | 换 partner 接口与服务商证书（见接入说明第六节） |
| `证书序列号错误` / 验签失败 | `WXPAY_SERIAL_NO` 填错，或私钥与序列号不匹配 | 到商户平台 API安全核对序列号 |
| `appid 与商户号不匹配` | 小程序 AppID 与商户号未绑定/主体不一致 | 商户平台 → 产品中心 → AppID账号管理 绑定 |
| prepay 返回 `{code:0}` 但前端拉起失败 | payParams 拼接错/package 丢了 `prepay_id=` | 检查 `buildMiniPayParams` 返回结构 |
| 回调日志 `验签失败` | 平台公钥过期/轮换或 rawBody 为空 | 更新 `wechatpay_pub.pem`；确认 main.ts `rawBody:true` |
| 回调收不到（无日志） | notify_url 不可达/域名未加白名单/被防火墙拦 | 用浏览器访问 notify 地址确认可通；查 Nginx 日志 |
| 用户已付款但订单一直待支付 | 回调丢失 | 见 4.4 主动查单；先查后端与商户平台日志对账 |
